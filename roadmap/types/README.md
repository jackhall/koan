# Types

What a type can say, and what type a value has. Generic code is typed as far
as its static types reach and checked by the call for the rest, so the items
here widen what the declarations can decide — a head's type reading its own
parameters, a static type pinning a parameter to a variable, an overload a
builtin always beats
refused whatever its signature, a projection by schema — settle what a value
carries where today's rule loses something, as at a view's barrier or a tail
call, and keep a solve blind to the order a union's members are written in.
What it buys the language: a program that states its types is refused early
where they decide it, each call checking only what the load could not decide,
and a program asking for decisions the build cannot bound is refused with the
declaration that would bound them
([the binding graph](../../design/binding-graph.md#refusal)). Where the load's pass runs, and where what
it settles lives, is [one build](../one-build/README.md)'s.

[The design](../../design/gradual-typing.md) follows a type from its
declaration to a call. The pieces sit in the [type lattice](../../lattice/src/types/README.md), the
[elaborator](../../src/elaborate/README.md) and
[dispatch](../../src/dispatch/README.md#static-types).

## Unplanned work

Known gaps with no item behind them yet — recorded so they are not rediscovered
as surprises, not scheduled.

- **A `USING` header at a meet of signatures stalls the run.** A
  [`USING … SCOPE`](../../src/scope/README.md#names-that-arrive-at-run-time)
  header whose ascription meets two signatures, as in
  `USING (pk :! ((Pick WITH {Carrier = Str}) & Named)) SCOPE (PICK x)`, loads,
  but its run stops on a refused step (`Step(Refused)`) instead of picking
  `PICK`'s overloads from the meet. It stalls alike whether the meet is closed or
  written over a run-bound name, so the test of header picks over a meet
  (`header_picks_over_a_carried_type_no_application_spells_are_a_fresh_load_s`)
  compares two runs that both stall.

- **A type value's static type is only its kind.** The load types a type
  value at the kind of the type it denotes, never at that type
  ([static types](../../src/dispatch/README.md#static-types)), so once a type
  passes through a name or a call no builtin's type rule can tell `Number` from
  `Str`: `ATTR` over a type (`Point.y` read as a value) and `|` and `&` over
  type values type their values no better than their declared kinds, and `:!`
  and `EVAL <code> -> <Type>` read their written types through node readings of
  their own rather than as operands of a builtin overload. A singleton static
  type for a type value — the type whose one value is the type value `Number` —
  would carry the denoted type through ordinary static typing. It is a
  [type lattice](../../lattice/src/types/README.md) change.
- **An instance site refused over an `Any` argument does not say how to fix
  it.** Where an argument at most `Any` is among those that solve an instance
  site's variables, the load refuses the site with "nothing fixes `Elt` here"
  ([instance sites](../../src/dispatch/README.md#static-types)). The message
  could name the argument and ask for a `FOR ALL` name on the declaration
  that binds it, or on a helper where nothing binds it.
- **A family cannot state its variance.** Every type-constructor family is
  covariant in its parameters, so a
  [parameterized union](../../src/elaborate/README.md#families) placing a
  parameter inside a function type's parameter list, or as a signature
  application's pin (`UNION (Elem -> Holder) = #{Has: :(Stack WITH {Elt = Elem}), Not: Null}`),
  is refused. Admitting one needs either a variance annotation on the
  declarator — contravariant, or invariant for a pin — or inference over its
  variants, and an order whose application arm reads each parameter's variance.
- **Whether `Module` and `Code` should re-stamp.** Every type that is one type
  re-stamps a value at itself, `Type` included, but `Module` and `Code`, the
  types every module and every quote satisfies, re-stamp nothing
  ([the type memo](../../src/values/README.md#the-type-memo-and-satisfies)).
  Were `Module` to re-stamp, a `-> Module` functor would hide all of its
  result's members. A quantifier does not stand in: a `FOR ALL #{Out: Module}`
  name only the return reads is solved to its bound, `Module`, so `-> Out`
  would hide them too. Each such functor would declare its result's signature
  or return `Any`. Undecided.
- **Anonymous structural recursion in types.** A data cycle ties only through
  a callable or a tagged nominal value
  ([the tie](../../src/knot/README.md#the-tie)), so `LET a = [1 a]` or a ring of
  plain record values needs a nominal declaration. Structural `μ`-types in the
  [type lattice](../../lattice/src/types/README.md) would admit them without
  breaking a program the nominal cut admits. They would also let the build
  infer the recursive union a
  [recursion that grows its type](../../design/binding-graph.md#refusal)
  is refused for want of, in the declaration's place.
- **The unfilled typing is a flag every write consults.** A quote's code is
  typed a second time with its unmarked holes empty, and the walk
  ([`walk.rs`](../../src/dispatch/walk.rs)) checks `unfilled` wherever that
  typing would keep a fact; `solved_from` falls back to carried types on a
  length mismatch rather than refusing. A typing whose writes have nowhere to
  land would let the types carry what the flag carries.
- **A projection's base rebuilt outside its bound panics.** A rebuild that
  replaces a projection's base by a type outside the base's bound panics in
  `reassemble` ([`unary.rs`](../../lattice/src/types/walk/unary.rs)): the piece
  of such a type does not exist, and the rebuild has no variance to pick an
  end. Today only `substitute_levels` reaches it, with bindings under their
  bounds; `read_through` reads a projection by its base and falls back to the
  projection's own end
  ([reading through intervals](../../lattice/src/types/solving.md#substitute-then-ask)).
  A level's binding that carried that it lies under its bound would make the
  check unable to fire.
- **A use's candidates are not checked for coverage at load.** A keyworded
  use in a quantified body is selected per binding, so a binding that leaves
  it no candidate is refused where it is bound. Under
  `EXPR FOR ALL #{Elt: :{size :Any}} #(DESCRIBE x :Elt) -> Str = #(SHOW (x.size))`,
  with `SHOW` at `Number` and at `Str`, `DESCRIBE {size = [1]}` is refused
  inside `DESCRIBE`, a body its caller did not write. Where the load sees
  every candidate, it could refuse the declaration unless the candidates'
  slots cover the argument read through the bound, and ask for the bound
  `:{size :(Number | Str)}` or a `SHOW` at `Any`. That is a new judgement,
  harder over several slots, and its dual — two candidates tying at some
  binding — has no bound that fixes it.
- **A head cannot project a `FOR ALL` name.** In a body `Elt.size` is the
  projection `(FIELD size OF Elt)` where `Elt`'s bound declares `size`
  ([what a body may ask of a `FOR ALL` name](../../design/quantified-types.md#what-a-body-may-ask-of-a-for-all-name)).
  In the head the name is a quantified variable, and `-> :(Elt.size)` is
  refused whatever the bound: `<quantified 0> has no member size`. Admitting
  it needs a
  [projection](../../lattice/src/types/vocabulary.md#the-node-vocabulary) over
  a quantified variable, a [type lattice](../../lattice/src/types/README.md)
  change, or a hidden variable as
  [a head reading its parameters](../../src/elaborate/README.md#a-head-reading-its-parameters)
  introduces.
