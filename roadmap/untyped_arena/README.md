# Untyped arena

Converts every composite value substrate to region-allocated, borrow-carried
storage and drives regions toward `Drop`-free untyped bump arenas — the storage
model pinned in [design/value-substrates.md](../../design/value-substrates.md).
What it buys the language: one ownership regime with no per-value refcounts, a
pinning escape (a region transfer is a refcount bump and a reach mint) with a
cost-driven copy that bounds how many regions the pins retain, O(1)
deallocation-only region death, and the deletion of the runtime residence
audits in favor of compile-enforced construction doors.

Read the design doc first: it pins the whole model and its
[§ Vocabulary](../../design/value-substrates.md#vocabulary) defines the terms
every item here uses (region, substrate, door, brand, witness, reach, pin,
seam, Drop-free). The value channel's conversion is done — every `Drop`-free
family lives in the region bump, index metadata included. What is left is
retiring the typed residue itself — `KFunction` and `Module` go `Drop`-free,
`Scope` moves beside the region as frame-owned droppy data (deleting the
typed-storage machinery and the `typed-arena` dependency), and the binding
tables go bump-backed so a scope's `Drop` is near-free — plus one storage
holdout (the operator registry's refcounted records) and one policy decision the
shipped cost seam makes local (evacuating a dying frame). The
`ContainerSubstrate<'a, C>` shape
([src/machine/model/values/container_substrate.rs](../../src/machine/model/values/container_substrate.rs))
is the realized pattern a later conversion copies: one `Copy` wrapper over cells,
a bump-hosted index, and a stored reach the doors derive.

## Unplanned work

Known gaps adjacent to this project's items, recorded so they aren't lost. **To start one,
first promote it into its own `roadmap/untyped_arena/<item>.md` file** with `**Problem.**` /
`**Acceptance criteria.**` / `## Dependencies` sections (see the documentation skill's
"When adding a new roadmap item"), then delete its prose entry here — a promoted item is
planned work and appears under `## Next items`, not here. These paragraphs name the gap,
not the fix.

- **The producer-failure sweep does not reach dispatch buckets.** When a binder node finalizes
  with an error, `Bindings::clear_placeholders_for_producer`
  ([src/machine/core/bindings.rs](../../src/machine/core/bindings.rs)) drops the failed
  producer's pending arms from `data` and `types` but leaves `functions` untouched, so a failed
  `FN` binder's pending overload slot survives its own failure and dies only under a later
  `write_overload` at the same `BindingIndex`. On a REPL-persistent scope that strands a
  scheduler-local `NodeId` into a later run, where it names a slot belonging to a different
  node — the exact hazard the name-side sweep exists to prevent, and a consumer that parks on
  it waits on a producer that will never wake it. The asymmetry predates the pending-arm
  reshape, which preserved it deliberately (see
  [design/execution/name-placeholders.md](../../design/execution/name-placeholders.md)); the
  reshape put the pending overloads in the same table the sweep already walks, so the gap is
  now visible in one place rather than split across two. The fix has a fork in it — make the
  sweep bucket-aware, or key the purge on the producer `NodeId` the pending slot already
  carries, as the name side does.
