# Rewrite

A clean re-implementation of the runtime over the modules the first
implementation proved out. The first runtime — `src/machine`, `src/builtins`,
the binary and `tests/`, now behind the `pending_rewrite` feature
([TEST.md](../../TEST.md#the-pending-rewrite)) — settled the general shape of
the language: which features it needs, how they relate, and which substrate
each rests on. It also accumulated the bugs and architecture decisions that
shape carried with it. The rewrite builds the runtime back up in layers, each a
module over the ones below it that carries its design doc as its own
`README.md`; [TEST.md](../../TEST.md#the-pending-rewrite) lists the modules in
place. [Values](../../src/values/README.md) sit on `memory`, since a value is
what every layer above passes around, and [scopes](../../src/scope/README.md)
sit on values and types, and the
[scheduler](../../src/scheduler/README.md) — the deferred-work drain, a koan
module over the cell substrate — sits on both. The items here complete the path
to running a program: the top level that turns a koan program into work for the
drain; function values, whose captured environment is a scope's
closure bindings, over `memory`'s [knot](../../src/memory/README.md#the-knot),
the shape mutually recursive functions and circular values are born in; dispatch
over both; modules beside functions; yielding iterators
above dispatch; and, last, the delete that takes the first runtime and
`workgraph` off disk. What it buys the language: one runtime whose
every layer was designed knowing the layers above it, with the old runtime's
workarounds left behind rather than carried forward.

## Unplanned work

Known gaps with no item behind them yet — recorded so they are not rediscovered
as surprises, not scheduled.

- **Effect order rests on launch order, not on a rule.** Two statements with no
  data dependency between them are ordered by when their units' counts reach
  zero ([the top level](top-level-on-the-scheduler.md)), which is the order they
  are written unless one has its dependencies met late — a statement satisfied by
  a later binder launches after a statement that was ready sooner. A `PRINT`
  whose position says it comes first can therefore print second. Chaining the
  statements that can have effects needs an effect analysis koan does not have,
  and is an effects item's to add.
- **`CLOSE OVER` limits what an `EVAL` can see.** The scope builder reports
  `CLOSE` and `CLOSE OVER` unsupported; which item gives them their rewrite
  home is undecided.
- **A shape containing `EVAL` retaining its defining scope across frames.**
  [Scopes](../../src/scope/README.md#names-that-arrive-at-run-time) resolve an
  `EVAL`'s free names through the same-frame activation chain; a link to a
  defining frame's activation is a cross-region read that needs a hold on that
  frame's cell, which is the callable layer's to wire.
- **A function value born outside a binder's root.** The
  [tie](../../src/function/README.md#the-tie) births a callable only for a
  binder whose right-hand side is a callable form at its root, or a combined
  form; a `FN` inside a list literal, or one called where it is written, has no
  birth path, and which item gives it one is undecided. A `FN` under a data
  member's constructor slot is the same gap: the tie asks the caller to
  evaluate it and refuses `Eager` until one can.
- **Union-variant construction in a cycle.** A nominal construction
  `(Ring {next = a})` reads its payload as a constructor slot, so a tagged ring
  reaches the [tie](../../src/function/README.md#the-tie); a union variant's
  construction (`Tree.Node x`) is an attribute form whose parts stay eager, so
  a ring through a union variant is an eager cycle.
- **Anonymous structural recursion in types.** A data cycle ties only through
  a callable or a tagged nominal value
  ([the tie](../../src/function/README.md#the-tie)), so `LET a = [1 a]` or a ring of
  plain records needs a nominal declaration. Structural `μ`-types in the
  [type lattice](../../src/type_lattice/README.md) would admit them without
  breaking a program the nominal cut admits.
- **Binding a knot's members walks the knot per member.**
  [`Knotted::of`](../../src/function/birth.rs) resolves member `index` through
  `knot.members().nth(index)`, O(n) per call, so binding a component's k
  members is O(k²). The knot has no index→member door, since an edge is minted
  only by a `KnotPlan`.
- **The submission table never gives an entry back.** A `UnitId` is an index
  into the [scheduler](../../src/scheduler/README.md#the-two-ways-a-cell-waits)'s
  entry arena, so a settled unit's entry stays where it is with only its work
  taken out. The arena is therefore sized by the units submitted over a whole
  run rather than by the units outstanding, which a program whose every
  statement is a unit grows without bound. A generational id, or a free list
  over settled entries, would bound it.
- **An `EVAL` shape is built into program storage on every run.**
  `Shape::for_eval` lays a fresh block shape down in program storage, which is
  never released during a run, so an `EVAL` evaluated in a loop grows it
  without bound. Memoizing the shape per quoted node and site would bound it.
- **Two AST laws still ride the old runtime.** In
  [src/parse/ast/tests.rs](../../src/parse/ast/tests.rs),
  `the_cache_agrees_with_a_recompute_and_rides_a_copy_and_a_resplice` checks a
  node's structural cache through the old runtime's `WorkingExpression`, and
  `structural_equality_is_the_same_part_sequence` checks quoted-code equality
  through `KObject`. Both are gated behind `pending_rewrite`, so neither runs,
  though [values](../../src/values/README.md) now owns what each exercises —
  the working expression and `Value::equals`. They cannot simply be re-pointed:
  `parse` sits below `values`, so a parse test naming `values` inverts the
  dependency, and `values`' suite has no access to the AST strategies they
  generate from.
- **`CATCH`'s declared return is `Any`.** The first runtime declared
  `Result {Ok = Any, Error = KError}`. The rewrite declares neither type, and a
  [builtin shape](../../src/parse/builtin_shapes.rs)'s return rests in a
  `static`, which cannot hold an application over declared types; nothing owns
  restoring it.
- **`UNARY OP <symbol> OVER <operand>` keeps no slot raw.** Its `…Returning`
  twin types the symbol slot `KExpression` and so keeps it raw; this one types
  both slots `Any`. Both are reserved buckets whose miss stays a miss only
  because nothing evaluates there today, so the asymmetry costs nothing yet and
  nothing owns resolving it. [Dispatch](dispatch.md), which decides bucket
  admission, is where it would be settled.
- **`parse` and the type lattice import each other.** The lattice names
  `parse`'s label and symbol types, and the
  [builtin shapes](../../src/parse/builtin_shapes.rs) name the lattice's `const`
  handles.
  Lifting the labels out of `parse` into a module below both would make the
  edge one-way.
- **Whether a cell parks in two slots or one is worth a second look once koan
  has steps.** [The substrate](../../cellgraph/README.md#the-contract-three-embedder-types)
  keeps one slot per habitat, chosen before any production step parked state:
  the rule is visible in `StepSlots` — an empty scratch slot is what hands the
  bump back — at the price of every step splitting its state in two at each
  park. The alternative is **one continuation over both brands**,
  `C::At<'here, 'scratch>`, at rest in one slot beside a bit the *substrate*
  writes and `names_scratch` reads in the scratch slot's place. Two store doors
  set it: a scratch-free door taking `C::At<'here, 'here>` writes `false`, and a
  scratch door taking `C::At<'here, 'scratch>` writes `true`; each erases on the
  way in, since the substrate cannot widen an opaque form whose variance it does
  not know. The liveness argument is the bit's. `'scratch` is invariant,
  quantified per `enter`, and never lengthens to `'here`, so a value that
  typechecks at `At<'here, 'here>` names no byte of the bump — every referent in
  its scratch position outlives `'here` — and the bump may be handed back under
  it; a value stored through the other door holds the reset off exactly as a
  full scratch slot does. The embedder answers nothing: a step that stops
  needing scratch rebuilds its state at the scratch-free type, which compiles
  only if that is true. Either way the continuation comes back at
  `At<'here, 'scratch>`, sound under a `false` bit because its scratch position
  names nothing shorter than `'here`. Two obligations come with it. The slot
  must stay take-and-store only: a door that peeked at a continuation at rest
  would let an invariant family write a `'scratch` reference into one whose bit
  says `false`. And a cell's death must drop the whole continuation when the bit
  is set, before any reset, rather than leave it for the disposal — its drop
  glue would otherwise run over a bump already handed back. What to weigh once
  steps exist: whether nearly every park carries both kinds of state and the
  steps would read better over one state value, against an argument that lives
  in a door signature and an unwritten no-peek rule rather than in the struct.
