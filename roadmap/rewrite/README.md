# Rewrite

A clean re-implementation of the runtime over the modules the first
implementation proved out. The first runtime settled the general shape of
the language: which features it needs, how they relate, and which substrate
each rests on. It also accumulated the bugs and architecture decisions that
shape carried with it. The rewrite builds the runtime back up in layers, each a
module over the ones below it that carries its design doc as its own
`README.md`. [Values](../../src/values/README.md) sit on `memory`, since a value is
what every layer above passes around, and [scopes](../../src/scope/README.md)
sit on values and types, and the
[scheduler](../../src/scheduler/README.md) — the deferred-work drain, a koan
module over the cell substrate — sits on both.
[Function values](../../src/knot/README.md), whose captured environment is a
scope's closure bindings, rest on `memory`'s
[knot](../../src/memory/README.md#the-knot) — the shape mutually recursive
functions and circular values are born in — and
[module values](../../src/knot/module/README.md) sit beside them, a module being a
knot node of its own whose members are read by slot, and
[the program](../../src/program/README.md) above them all turns a loaded koan
program into work for the drain. The items here complete the path to running a
program: the lattice, value, scope and callable pieces dispatch rests on;
dispatch over all of them; and module programs and yielding iterators above dispatch. Three bodies of work that build on dispatch have projects of
their own: [conditionals](../conditionals/README.md) (matching, faults and catching),
[gradual typing](../gradual-typing/README.md) and
[metaprogramming](../metaprogramming/README.md). What it buys the language: one runtime whose
every layer was designed knowing the layers above it, with the old runtime's
workarounds left behind rather than carried forward.

## Unplanned work

Known gaps with no item behind them yet — recorded so they are not rediscovered
as surprises, not scheduled.

- **Effect order rests on unit order, not on a rule about effects.** A body's
  units are performed in the order its shape numbers them
  ([units](../../src/scope/README.md#units)), which is the order they are
  written except where a forward reference moves a binder ahead of its reader.
  A statement with an effect that reads a later binder therefore runs after a
  statement written below it. Giving effects an order
  of their own needs an effect analysis koan does not have, and is an effects
  item's to add: effects chained through a monad form a buffer that can be
  reordered by source span.
- **The overlap check skips quantified registrations.** The load-time
  [overlap check](../../src/dispatch/README.md#the-overlap-check) types only a
  registration that binds no `FOR ALL` group, so
  `EXPR FOR ALL #[Elt] #(x :Elt + y :Elt) -> Str` loads beside the builtin `+`,
  which wins every call the two share.
- **Every consumer writes its own descent.** An
  [`ExpressionPart`](../../src/parse/ast.rs) is walked by five descents in the
  shape builder (`part_marks`, `walk_part`, `walk_definition_part`,
  `rewrite_part`, `within_part`) beside the evaluator's and statics' leaf
  walks, with identical container arms; the lexical lookup
  ([resolution](../../src/scope/README.md#resolution)) is written five times,
  each a `channels().find` plus `sees`, a stop at `Program | Code` and a step
  out through the boundary; `landing` and `opens` are one capture-chain walk
  with two stop conditions; the value
  [digest](../../src/values/README.md#content-digests) walk in `digest.rs` and
  the [copy](../../src/values/README.md#crossing) walk in `crossing.rs` are the
  same explicit-stack frame over `Surface`, differing only in their leaf and
  finish actions, and the digest's `Tag` enumerates every layer's domain though
  `values` is opaque to modules; `erase_rigid` and `bound_above` in the
  [type lattice](../../lattice/src/types/substitute.rs) are two "replace a
  variable by its bound" walks. The walked type would own the traversal:
  `ExpressionPart::children()`, one `lookup` iterator the five consumers
  filter, one `Surface` frame driver with `leaf`, `finish` and `knot` hooks
  that the copy and the digest instantiate. The lattice half is a flagged
  exception needing an OK.
- **A flag or an overloaded field where a sum type belongs.** `Static::Unknown`
  in [statics](../../src/dispatch/statics.rs) also means "read at a call's
  head"; `across(inwards: bool)` in [the coercion](../../src/knot/module/coerce.rs)
  selects by flag, so `from` and `to` invert meaning after the swap;
  `KBirth::Block.module` is an `Option<KValue>`, so the `USING` path asks "is
  a module" three times; `Unlisted` is anchored at the use site for a type name
  and at the `OVER` list for a value name, which threads a `SourceRef` through
  six signatures, and `surfacing: Option<Parametric>` rides through
  `visit`/`nested` with every caller but one passing `None`. Each wants a
  variant per meaning, or an orientation fixed once rather than passed.
- **Write-once cells are guarded by `debug_assert` alone.**
  [`BodyShape`](../../src/scope/shape.rs)'s eight `fix_*` setters,
  `refuse_typing` and `TypeExpression::fix` each check for a prior write only
  in debug builds; `refuse_typing` has two writers (the elaborator's channel
  and dispatch's statics) kept apart by `done()`; the `unfilled` guard is
  repeated at eight write sites in statics while `fix_born_instance` bypasses
  `Level` and `fix`; `solved_from` falls back to carried types on a length
  mismatch rather than refusing. A crate-private `WriteOnce<T>` that refuses a
  second write, setters reachable from the load passes alone, and a `Level`
  that collects born instances with `fix` as the one gate would let the types
  carry what the asserts carry.
- **Refusals are re-listed layer to layer.**
  [`errors.rs`](../../src/dispatch/errors.rs) re-lists `view::Unascribable` one
  to one and hand-maps it with an `unreachable!` arm;
  [`ShapeError`](../../src/scope/shape.rs) holds fourteen dispatch variants and
  two elaborator ones, so every new static check edits `scope`; the module
  coercion builds `SealRefused::NotSealed`, which `values` never does, and
  reports a payload failing `satisfies` as "not sealed";
  `Unascribable::NotAModule` is `unreachable!` at its one caller. A refusal
  type would own its `display`, as `CoercionRefused` does, and be embedded
  upward rather than re-enumerated; an `unreachable!` arm in a mapping marks a
  variant that belongs to another type or is dead. Splitting `ShapeError` into
  a build half and a load half rendered in dispatch waits on the refusal cell
  holding a type `scope` does not own.
- **A `Shares` tail hop leaves its bytes in the host.** A tail recursion holds a
  constant number of cells ([tails](../../src/program/README.md#frames-contracts-and-tails)),
  but a hop placed `Shares` lays the next frame's activation and argument
  record down in the region of the cell it shares, which reclaims nothing until
  that cell finishes, so the recursion's memory still grows with its depth.
- **A receipt run is laid down anew at every park.** A parked cell's receipt run
  is laid down fresh in its scratch habitat per registration
  ([the cell](../../cellgraph/README.md#the-cell)), so a runner that parks once
  per unit lays one down per unit, where a registration that fits the previous
  run could reuse its bytes. Reuse would be a `cellgraph` change.
- **No warning channel.** A program has no way to be told about something
  that is neither an error nor a value. The first case with nothing to report
  through is [dispatch](../../src/dispatch/README.md#the-overlap-check)'s: a user overload that is never selected,
  because at its instantiated operand type a builtin is chosen first. The second is a
  keyworded use written unmarked in a quote ([holes](../../src/scope/README.md#holes-and-marks)), whose key has registrations
  visible where it is written that the quote will not see.
- **A type value's static type is only its kind.** The load types a type
  value at the kind of the type it denotes, never at that type
  ([static types](../../src/dispatch/README.md#static-types)), so once a type
  passes through a name or a call no builtin's type rule can tell `Number` from
  `Str`: `ATTR` over a type (`Point.y` read as a value) and `|` and `&` over
  type values type their values no better than their declared kinds, and `:!`
  and `EVAL <code> -> <Type>` read their written types through node readings of
  their own rather than as operands of a builtin overload. A singleton static
  type for a type value — the type whose one value is the type value `Number` —
  would carry the denoted type through ordinary static typing. It is a
  [type lattice](../../lattice/src/types/README.md) change.
- **`CLOSE OVER` limits what an `EVAL` can see.** The scope builder reports
  `CLOSE` and `CLOSE OVER` unsupported; which item gives them their rewrite
  home is undecided.
- **Union-variant construction in a cycle.** A nominal construction
  `(Ring {next = a})` reads its payload as a constructor slot, so a tagged ring
  reaches the [tie](../../src/knot/README.md#the-tie); a union variant's
  construction (`Tree.Node x`) is an attribute form whose parts stay eager, so
  a ring through a union variant is an eager cycle.
- **Anonymous structural recursion in types.** A data cycle ties only through
  a callable or a tagged nominal value
  ([the tie](../../src/knot/README.md#the-tie)), so `LET a = [1 a]` or a ring of
  plain records needs a nominal declaration. Structural `μ`-types in the
  [type lattice](../../lattice/src/types/README.md) would admit them without
  breaking a program the nominal cut admits.
- **Binding a knot's members walks the knot per member.**
  [`Knotted::of`](../../src/knot/tie.rs) resolves member `index` through
  `knot.members().nth(index)`, O(n) per call, so binding a component's k
  members is O(k²). The knot has no index→member door, since an edge is minted
  only by a `KnotPlan`.
- **A cyclic data value cannot cross an opaque view's barrier.** The
  [coercion walk](../../src/knot/module/README.md#members-are-born-coerced) rebuilds
  a container cell by cell, but a container that is a knot's data node is a knot
  member rather than a container word, so the arm has nothing to rebuild and
  refuses `Unsupported`. Rebuilding a cycle through a barrier would have to
  re-tie the knot under the view's types, which nothing does.
- **A dict's keys cross an opaque view's barrier unsealed.** The
  [coercion walk](../../src/knot/module/coerce.rs) leaves a dict's keys
  untouched while it restamps the dict at `MAP <carrier> -> …`, so a key read
  back from the view carries the source's scalar type rather than the carrier
  its dict type names.
- **A `:!` view carries a nested module without its pinned parameters.** Under
  `:!` the [coercion walk](../../src/knot/module/coerce.rs) carries a nested
  module verbatim, so a head parameter its slot's application pins is no member
  of it, though a top-level view lays each parameter down as one. With `inner`
  declared at `Inner WITH {Elem = Number}` and defining no `Elem`, the load
  types `v.inner` then `.Elem` at the pin and the run faults `has no member
  Elem`. Re-viewing a nested module at its declared application would make the
  pin a member.
- **A family cannot state its variance.** Every type-constructor family is
  covariant in its parameters, so a
  [parameterized union](../../src/elaborate/README.md#families) placing a
  parameter inside a function type's parameter list is refused. Admitting one needs either a
  variance annotation on the declarator or inference over its variants, and
  an order whose application arm reads each parameter's variance.
- **A nominal over a run-bound type is declared per call.** A `NEWTYPE` or
  `UNION` whose definition names a type a run binds — `NEWTYPE Box = :{v :Elt}`
  in a `FOR ALL #[Elt]` body — has no load-time handle
  ([the type channel at load](../../src/elaborate/README.md#the-type-channel-at-load)):
  a sealed group is a leaf substitution never enters, and a nominal's identity
  is its name and schema, so each call's `Box` is a different type. It is declared through the activation
  each time its unit runs. A lattice door that substitutes into a sealed group
  and re-seals it would give the same handle from one load-time declaration.
- **A cycle through a family construction has no cut.** A construction through
  a [family](../../src/values/README.md#what-a-value-is) solves its type from its payload, so the
  [tie](../../src/knot/README.md#the-tie) derives it like a container, and a
  cycle through family constructions alone refuses as `TypeCycle`. A
  self-containing list is no loss: `NEWTYPE Nest = :(LIST OF Nest)` then
  `LET a = (Nest [a])` ties, typing `a` more precisely than any family
  application could. What has no spelling is a cyclic value whose type *is* a
  family application — a tree pointing back into itself that still passes where
  `:(Tree {Elem = Number})` is declared, which a bespoke nominal type would not.
  A construction through an applied family head would give one:
  `LET NumNode = :(Tree.Node {Elem = Number})` then
  `LET t = (NumNode {value = 1, left = t, right = t})` fixes `t`'s type before
  its payload is read, so the tie cuts there, and the payload is checked
  against the representation with the arguments substituted in. Today an
  applied head constructs nothing.
- **`CATCH`'s declared return is `Any`.** The first runtime declared
  `Result {Ok = Any, Error = KError}`. The rewrite declares `Result`
  ([`builtin_result`](../../src/elaborate/builtin.rs)) but no `KError`, and a
  [builtin shape](../../src/parse/builtin_shapes.rs)'s return rests in a
  `static`, which cannot hold an application over declared types.
  [Catching errors](../conditionals/catching.md) names `Result`
  there, and has to get past that.
- **A value's weight counts a knot once per reference.** A knot member weighs
  its whole knot ([weight](../../src/values/README.md#weight)), and a
  composite's weight is the sum of its cells', so a value holding two members
  of one knot weighs that knot twice, though a crossing copies it once. The
  verdict then leans toward pinning. A memoized weight cannot see sharing below
  it without a set of knots per composite.
- **Whether a cell parks in two slots or one is worth a second look once koan
  has steps.** [The substrate](../../cellgraph/README.md#the-contract-three-embedder-types)
  keeps one slot per habitat, chosen before any production step parked state:
  the rule is visible in `StepSlots` — an empty scratch slot is what hands the
  bump back — at the price of every step splitting its state in two at each
  park. The alternative is **one continuation over both brands**,
  `C::At<'here, 'scratch>`, at rest in one slot beside a bit the *substrate*
  writes and `names_scratch` reads in the scratch slot's place. Two store doors
  set it: a scratch-free door taking `C::At<'here, 'here>` writes `false`, and a
  scratch door taking `C::At<'here, 'scratch>` writes `true`; each erases on the
  way in, since the substrate cannot widen an opaque form whose variance it does
  not know. The liveness argument is the bit's. `'scratch` is invariant,
  quantified per `enter`, and never lengthens to `'here`, so a value that
  typechecks at `At<'here, 'here>` names no byte of the bump — every referent in
  its scratch position outlives `'here` — and the bump may be handed back under
  it; a value stored through the other door holds the reset off exactly as a
  full scratch slot does. The embedder answers nothing: a step that stops
  needing scratch rebuilds its state at the scratch-free type, which compiles
  only if that is true. Either way the continuation comes back at
  `At<'here, 'scratch>`, sound under a `false` bit because its scratch position
  names nothing shorter than `'here`. Two obligations come with it. The slot
  must stay take-and-store only: a door that peeked at a continuation at rest
  would let an invariant family write a `'scratch` reference into one whose bit
  says `false`. And a cell's death must drop the whole continuation when the bit
  is set, before any reset, rather than leave it for the disposal — its drop
  glue would otherwise run over a bump already handed back. What to weigh once
  steps exist: whether nearly every park carries both kinds of state and the
  steps would read better over one state value, against an argument that lives
  in a door signature and an unwritten no-peek rule rather than in the struct.
