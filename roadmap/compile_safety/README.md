# Compile safety

The compile-enforcement path for koan's memory abstraction: every way
koan-implementation Rust with no `unsafe` block can under-pin a region (dangle)
or over-pin one (leak / retention) becomes a compile error or a library-run
check. No residence walk over a composite value survives, no runtime residence
check survives, and a region keeps no address side table for one to consult: a
move-in is discharged by the door's signature — a region-free leaf type, a fold
brand's rank-2 capability, a born door's rank-2 brand over the destination, or a
merge whose composition derives the reach. `src/` carries no `unsafe` at all,
tests included. The remaining work is the hotspot-map holes below, each
promoted to its own roadmap item. Tier vocabulary:
[memory-model.md § Move-in residence](../../design/memory-model.md#move-in-residence).

## Unplanned work

Known holes in the memory abstraction — ways koan-implementation Rust with no
`unsafe` block can still under-pin a region (dangle) or over-pin one
(leak / retention). The hotspot map below covers every hole; a row whose hole
links to a roadmap item is promoted, and that item owns the problem statement
and fix. A hole recorded after the map as prose rather than as a map row is a
not-yet-promoted candidate, kept there so it isn't lost. **To start one, first
promote it into its own
`roadmap/compile_safety/<item>.md` file** with `**Problem.**` /
`**Acceptance criteria.**` / `## Dependencies` sections (see the documentation
skill's "When adding a new roadmap item"), then replace its prose entry here
with a link in the map. Do not implement from these paragraphs directly — they
name the hole, not the fix.

Several entries assume the tier vocabulary of
[memory-model.md § Move-in residence](../../design/memory-model.md#move-in-residence)
(the region-free-leaf doors, the fold capability, and the born doors); read that
section first.
